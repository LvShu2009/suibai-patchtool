# SU 脚本 · 操作指南（修订版 v2）

三个脚本，全部保持**原来的 su（root）权限模型**：不考虑权限访问问题，直接 su 驱动。
改的只有逻辑和健壮性。

---

## 1. 三个脚本干什么

| 脚本 | 用途 | 调用方式 |
|---|---|---|
| `自动安装补丁.sh` | 把 `补丁存放位置（zip）/*.zip` 全装进游戏 | `sh /storage/emulated/0/LvShu/酸败补丁/自动安装补丁.sh` |
| `自动打包补丁文件.sh` | 把 `打包补丁/待打包资源/` 打成标准 zip | `sh 自动打包补丁文件.sh 'data/android/assetbundle/prefabs/heroes'` |
| `创建所需文件夹.sh` | 建整套目录结构 | `sh 创建所需文件夹.sh` |

**不需要自己先敲 su**：脚本开头会自己判断，不是 root 就 `exec su -c "sh '$0'"` 提权一次，
之后全程 root 执行（本质还是 su，只是一次到位）。

在 MT 管理器 / Termux / 任意终端里直接 `sh 脚本名` 就行，会弹一次 root 授权。

## 2. 原始版 → 修订版 改了什么

### 自动安装补丁.sh

| # | 原始版问题 | 修订版 |
|---|---|---|
| 1 | `find "$TMP_DIR/files"` 硬依赖 `files/` 前缀，裸文件包会**静默部署 0 个文件却打印「✓ 解压完成」** | 自动判断结构：有 `files/` 用 `files/`，没有就用包根；一个文件都没装时明确打 `⚠ 这个补丁一个文件都没部署` |
| 2 | 完全没有备份，覆盖即不可逆 | 覆盖前备份到 `备份文件/原版/`，写 cksum 索引（与 APP 同一个格式，APP 能一键回滚） |
| 3 | 没有备份判断，重复跑会把已打补丁的版本当原版 | 只备份一次；**内容和补丁相同的文件不备份**；同名顶替会被 cksum 发现并告警 |
| 4 | 日志最后一次性 `su -c "echo '$LOG_BUFFER' > 文件"`：中途崩一个字不剩，内容含单引号会截断命令 | 每行日志**即时追加**，崩了也能看到进度 |
| 5 | 每步都嵌一层 `su -c "..."`，路径带空格/引号极易炸 | 开头提权一次，后面直接跑，引号地狱消失 |
| 6 | 结束没有统计 | 结尾汇总：补丁几个、文件几个、成功几个、失败几个 |

### 自动打包补丁文件.sh

| # | 原始版问题 | 修订版 |
|---|---|---|
| 1 | 必须手动输入路径 | 支持命令行直接给路径，不给才交互 |
| 2 | 依赖系统 `zip`，缺了直接报错看不懂 | 先检测，缺了给出替代方案（用 APP 的打包按钮） |
| 3 | 中途 Ctrl-C 会留下 `补丁素材源文件/tmp_*` | `trap` 兜底清理 |
| 4 | 输出目录是补丁根目录 | 直接输出到 `补丁存放位置（zip）/`，装完就能被安装脚本扫到 |

### 创建所需文件夹.sh

| # | 原始版问题 | 修订版 |
|---|---|---|
| 1 | 用了 bash 数组 `DIRS_TO_CREATE=(...)`，`/system/bin/sh` 是 mksh，**直接语法报错** | 改成 POSIX 循环，任何 sh 都能跑 |
| 2 | `tree` 不存在，输出一片报错 | 去掉 tree，用 `ls -ld` |
| 3 | 没建 `备份文件/原版`（备份要用的目录） | 补上，并顺带建 `打包补丁/待打包资源` |
| 4 | 失败也继续往下跑 | 统计失败个数，结尾给结论 |

## 3. 与 APP 的配合

两边**共用同一套备份**：

```
备份文件/原版/<相对路径>         ← 原始文件
备份文件/原版/.manifest.tsv      ← 相对路径 TAB cksum TAB 字节数
```

- SU 脚本装的补丁，可以点 APP 的「↩ 一键回滚原版」还原
- APP 装的补丁，也能被 SU 脚本的备份逻辑继续追加（同一份索引）
- 两边都不会重复备份、都不会把"已经是补丁"的文件当原版存

---

## 4. 注意

- 脚本里的路径是写死的（`/storage/emulated/0/LvShu/酸败补丁`），换目录要改文件头的变量
- 路径含空格时，调用要加引号：`sh 自动打包补丁文件.sh 'a b/c'`
- 解压中转用 `/data/local/tmp/patch_tmp`（重启会清空，无所谓，每次都会重建）
- 老设备可能没有 `zip`/`unzip`，缺 `zip` 就用 APP 的打包按钮
- 日志在 `操作日志/install_su_<时间戳>.log`，与 APP 的 `install_<时间戳>.log` 分开放

---

## 5. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 脚本一跑就退出、没有日志 | 没给 root 授权；或路径写错（改文件头变量） |
| 「游戏目录不存在，退出」 | 渠道服包名不是 `com.jumpw.mobile300`，改脚本里的 `GAME_DIR` |
| 「⚠ 这个补丁一个文件都没部署」 | zip 里既没有 `files/` 也没有可识别的文件；检查 zip 内容 |
| 「⚠ 备份校验不符（疑似同名顶替）」 | 备份目录里那个文件被别的同名文件换过了；脚本不会改索引，回滚也会跳过它 |
| 安装成功但游戏没变 | 确认装的是对应渠道的资源；确认游戏重启过 |
| `zip: command not found` | 用 APP 的「📦 打包」按钮代替 |

## 6. 三个脚本完整用法示例

```sh
# 1) 首次准备
sh /storage/emulated/0/LvShu/酸败补丁/创建所需文件夹.sh

# 2) 把补丁 zip 丢进 补丁存放位置（zip）/，然后
sh /storage/emulated/0/LvShu/酸败补丁/自动安装补丁.sh

# 3) 自己做一个补丁：把文件放进 打包补丁/待打包资源/，然后
sh /storage/emulated/0/LvShu/酸败补丁/自动打包补丁文件.sh 'data/android/assetbundle/prefabs/heroes'
# 输出：补丁存放位置（zip）/补丁_<时间戳>.zip（内部结构 files/data/android/...）
```
