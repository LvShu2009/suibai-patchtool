酸败补丁助手 v2.1 · 操作指南

一个免 root 的补丁安装器：权限走 Shizuku，替代原来的 su 脚本。

装补丁、开反和谐、备份、回滚、清理，都在一个界面里点。

---

1. 环境要求

项要求
Android8.0 以上（minSdk 24 / targetSdk 33）
Shizuku已安装、已启动、已授权给本 APP（API 13.x）
存储权限「所有文件访问权限」（Android 11+）或读写存储（Android 10-）
游戏需先装好，酸败官服包名 com.jumpw.mobile300
Android/data/ 对普通应用进程是不可见的（系统限制，不是 bug）。
所以「目录是否存在」「拷贝文件」全部由 Shizuku 的 shell 执行，
界面里的「探测」也是走 shell，不是应用自己去看目录。

---

1.5 两条执行通道（任选其一）

工具不再强制依赖 Shizuku，root 和 Shizuku 两条路并存：

通道怎么来特点
root（su）设备已 root，勾选配置里的「优先用 root 执行」身份真 uid=0，脚本走 /data/media/0，不碰 FUSE，能 chown 给游戏、能写 root 拥有的目录；不需要激活 Shizuku
Shizuku装 Shizuku 并授权本应用身份是 shell(uid=2000) 或 root(uid=0，若用 root 激活)；shell 激活时偶尔会遇到挂载点失效

选择逻辑：勾了「优先用 root」且探测到可用 su → 走 root；否则自动回落到 Shizuku。

状态栏第一行会直接写当前走的是哪条、什么身份。

2. 首次使用

  1. 安装 酸败补丁助手.apk（作者签名，覆盖安装无需卸载）。
  2. 选一条通道：
  • 有 root：勾上配置里的「优先用 root 执行」，第一次运行会弹 su 授权，点允许即可（不用开 Shizuku）
  • 没 root：点 ① 授权 Shizuku → 弹窗里点「允许」
  1. 点 ② 文件访问权限 → 系统设置里给「所有文件访问」。
  2. 点 🔍 自动探测已安装的酸败目录（渠道服必须点；官服可跳过）。

状态栏第一行显示 执行通道：root（su）· uid=0 或 执行通道：Shizuku · uid=…，且第二行两项都正常，就能干活了。

5. 备份与回滚（重点）

备份规则

  • 所有备份统一放 备份文件/<包名>/原版/，同一个文件只备份一次，之后永不覆盖。
  • 备份时写索引 备份文件/原版/.manifest.tsv，每行三个字段（TAB 分隔）：

    • 相对路径 ⇥ cksum ⇥ 字节数

  • 判断「是不是真的备份过」靠 cksum，不靠文件名 —— 同名文件顶替会被发现。

四种情况分别怎么处理

情况行为
备份不存在覆盖前先备份，写索引，日志「已备份原版」
备份存在且校验一致跳过，日志「备份已有（校验一致，跳过）」
备份存在但没索引（老备份）只补记索引，不动文件：日志「备份已存在，补记校验索引」
备份校验不符（同名顶替）只告警，不改索引，回滚时拒绝这个文件

不会被误备份的两类

  • *.txt / *.md 说明文件：它们不是游戏原版
  • 内容和补丁一模一样的文件：说明它本来就已经是补丁，日志「与补丁内容相同，不备份（不是原版）」

回滚规则

  • 逐个按索引核对 cksum，对得上才拷回，并 chown 给游戏、chmod 0664
  • 校验不符 → 跳过并告警（防止把错的文件盖进去）
  • 备份内容与当前文件一致 → 提示「无需还原」（说明当初备份的已是补丁）
  • 说明文件 → 直接跳过
  • 结尾统计：还原 N 个，跳过 N 个，失败 N 个
建议回滚前先退出游戏，避免资源被游戏进程锁住。

6. 清理备份

点 🧹 一键清理备份 会先报家底（原版几个文件多少 MB、旧时间戳目录几个多少 MB），然后三选：

  • 删旧目录：只删 yyyyMMdd_HHmmss 形式的旧备份，原版 保留（推荐）
  • 全部删除：连 原版 一起删，之后就没法一键回滚了
  • 取消

安全边界：只认这两种目录名，你自己放进去的其它文件夹一律不碰；

脚本发现路径不是 …/备份文件 会直接中止（一个文件都不删）。

6.4 备份会不会重复、会不会把补丁当原版

不会。装补丁时脚本对每个文件按顺序判断：

  1. 当前文件内容和补丁完全相同 → 判定"不是原版"，不备份（日志：与补丁内容相同，不备份）
  2. 备份文件已存在 → 永不覆盖；索引（.manifest.tsv）里已有记录就跳过（日志：备份已有（校验一致，跳过））
  3. 备份存在但索引里没有 → 只补记索引，不动文件
  4. 备份存在但校验不符 → 报 ⚠ 备份校验不符（疑似同名文件顶替），不覆盖、回滚时也拒绝这个文件

另外 v3.1 起还多一条：如果备份内容居然和补丁一模一样，会报

⚠ 备份内容和补丁一模一样，这份备份是假的（当初备份到的就是补丁），回滚它等于没回滚 —— 这类历史遗留的"假原版"能一眼看出来。

6.5 安装前自检与退出码

每次安装/回滚动手之前会先试写一个探测文件（touch），写不进去就直接中止：


✗ 游戏目录当前不可写（挂载点失效），已中止，一个文件都没动

这样不会出现"装到一半才发现挂载点挂了"。

退出码含义
0全部成功
2无法进入解压目录
3游戏目录不存在
4备份目录不存在（回滚）
5备份路径不合法，拒绝删除（清理）
6找不到可写的挂载点
7自检失败：目录当前不可写
8有文件写入/还原失败（日志会点名几个）

9. 常见问题

Q：提示「游戏目录不存在」？

Android/data 普通应用看不到是正常的。先确认 ① Shizuku 已授权，再点 🔍 探测。

渠道服包名不是 com.jumpw.mobile300，要以探测结果为准。

Q：以前报 Transport endpoint is not connected？

Android 11+ 的 FUSE 目录在 shell 里偶尔抽风。v1.2 起：shell 是 root 时自动把

/storage/emulated/0/... 换成 /data/media/0/... 直连，并带重试，已不会再出现。

Q：界面白字白底看不清？

v1.1 起强制浅色主题、所有颜色写死，不跟随系统深色模式。

Q：安装完游戏里没变化？

先看日志结尾的「合计 N 个文件」。如果是 0，说明 zip 里没有 files/ 目录结构

（裸文件包），日志会明确打 ⚠ 这个补丁一个文件都没部署。

老脚本就是在这里静默失败的。

Q：想恢复某个补丁前的内容？

点「↩ 一键回滚原版」。如果日志说「无需还原」，说明当初备份下来的已经是补丁，

这个文件没有原版可回。

Q：Shizuku 重启后失效？

重新点 ① 授权即可。Shizuku 本身被系统杀掉要重新启动 Shizuku。

Q：能不能不用 Shizuku，直接用 su？

可以，见同目录 SU脚本操作指南.md，两套工具共用同一份备份索引，互相兼容。
