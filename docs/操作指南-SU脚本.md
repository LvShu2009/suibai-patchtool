# SU 脚本 · 操作指南（v3.14，对齐 APP v3.14）

三个脚本全部保持 **su（root）驱动**：脚本开头自己判断，不是 root 就 `su` 一次，之后全程 root 执行。
逻辑上已经和 APP v3.14 对齐，不再各写一套。

---

## 1. 三个脚本

| 脚本 | 用途 | 调用方式 |
|---|---|---|
| `自动安装补丁.sh` | 把 `补丁存放位置（zip）/*.zip` 装进游戏 | `su -c "sh 自动安装补丁.sh"` |
| `自动打包补丁文件.sh` | 把 `打包补丁/待打包资源/` 打成标准 zip | `su -c "sh 自动打包补丁文件.sh data/android/assetbundle/xxx"` |
| `创建所需文件夹.sh` | 建整套目录（含 CAB 索引缓存目录） | `su -c "sh 创建所需文件夹.sh"` |

不用自己先敲 `su`。在 MT 管理器 / Termux / 任意终端里直接 `sh 脚本名` 就行，会弹一次 root 授权。

## 2. 安装脚本

### 常用写法

```sh
# 自动探测游戏目录，装补丁目录里的全部 zip
su -c "sh 自动安装补丁.sh"

# 渠道服：只给包名，路径自动展开
su -c "sh 自动安装补丁.sh --pkg com.jumpw.mobile.aligames"

# 路径不在常规卷下、或想强制指定
su -c "sh 自动安装补丁.sh --game /storage/emulated/0/Android/data/com.jumpw.mobile300/files"

# 只装一个包
su -c "sh 自动安装补丁.sh --zip 补丁_20261114.zip"

# 先看会做什么，不备份也不写游戏
su -c "sh 自动安装补丁.sh --dry-run"

# 只装游戏里已有的文件，不按包内路径新增（APP 的严格判定）
su -c "sh 自动安装补丁.sh --strict"
```

### 它做了什么

1. 定位游戏目录：`--game` > `--pkg` > 扫 `Android/data/com.jumpw.*`，官服 `mobile300` 优先。
2. 选卷：`/data/media/0` 优先，其次 `/storage/emulated/0`，再退 `pass_through` / `mnt` 视图。
3. 建备份目录：`备份文件/<包名>/原版/`；发现老的 `备份文件/原版/` 且包名目录还不存在时自动归档过去。
4. 解压：`python3`（按 UTF-8 标志解码，GBK 包做试探）→ `unzip` 默认 → `unzip -O GBK` → `unzip -j` 扁平 → busybox；每次失败的真实报错都会写进日志。
5. 路径优先级：包内带 `files/` 根的条目**第一优先级直装**（按 `/files/` 后的路径写入，不找同名、不比 CAB）；没有 `files/` 根的包才走精确 → 剥皮 → 同名唯一 → CAB。
6. 过滤：png/jpg/jpeg/md/txt 不装；`localmode.txt` 例外，落在游戏根目录。
7. 新增：精确路径在游戏里没有对应资源时，按**归一化路径**新建（重复前缀只剥多余那层、真实 `flies` 保留，`flies/flies/...` → `flies/...`）；首级目录必须是游戏 `files` 下真实存在的目录，绝对路径 / `..` / `assets/` 一律不建；`--strict` 可关闭新增。
8. 备份：目标已存在、备份里还没有这份文件时，先备份再覆盖，并写 `.manifest.tsv`。
9. 写入：写前探测可写，`mkdir`/`cp` 各三次重试，失败会尝试切换挂载点。

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 正常结束 |
| 3 | 找不到 / 不存在游戏目录 |
| 4 | 临时目录建不出来 |
| 5 | 补丁目录或指定 zip 不存在 |
| 7 | 游戏目录当前不可写（挂载点失效） |
| 8 | 有文件没写进去（部分失败） |
| 9 | 已有安装进程在跑 |

## 3. 打包脚本

```sh
su -c "sh 自动打包补丁文件.sh data/android/assetbundle/texture/heropanel"
su -c "sh 自动打包补丁文件.sh --rel data/android/assetbundle --out 我的补丁.zip"
```

- 相对路径会剥掉 `files/`、`/storage/emulated/0/`、`/data/media/0/`、`/sdcard/` 等前缀。
- 含 `..` 段的路径直接拒绝，防止 root 下把内容写到临时目录之外。
- 产物固定为 `files/<相对路径>/…`，和 APP 的「📦 打包」按钮同构。
- 打完会检查内部结构，输出到 `补丁存放位置（zip）/补丁_<时间>.zip`。

## 4. 目录结构

```
LvShu/酸败补丁/
├── 补丁存放位置（zip）/     ← 要装的 zip 放这里
├── 备份文件/
│   ├── 原版/               ← 老目录，首次使用会归档到包名下
│   └── <包名>/原版/        ← 新备份 + .manifest.tsv
├── 补丁素材源文件/         ← 打包临时目录
├── 打包补丁/待打包资源/    ← 打包源
├── 操作日志/               ← install_su_<时间>.log
├── 临时解压/
└── 缓存/资源索引/          ← APP 的 CAB 索引缓存
```

## 5. 和 APP 的关系

| 能力 | SU 脚本 | APP |
|---|---|---|
| 安装 / 回滚 | 安装脚本 + APP 回滚共用索引 | 完整 |
| 备份隔离 | 按包名 | 按包名 |
| CAB 消歧 | 现场读 CAB 头，按需比对 | 建索引缓存，速度更快 |
| GBK 包 | 有 `python3` / `unzip -O` 最稳；都没有时退扁平解压 | Java 侧处理，最稳 |
| Shizuku 通道 | 不支持 | 支持 |
| 进度显示 | 日志行 | 进度条 |

结论：root 机器用脚本更省事；Shizuku、超大包、GBK 老包优先用 APP。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| `✗ 找不到游戏目录` | 游戏没装或包名不是 `com.jumpw.*`；用 `--pkg` / `--game` 指定 |
| `✗ 游戏目录当前不可写` | 重启手机或终端后重试；确认 `/data/media/0/Android/data/<包名>/files` 存在 |
| 某个文件 `⚠ 定位不到目标` | 包里路径与游戏不一致，且同名文件也找不到；用 APP 的精确路径模式再试 |
| `⚠ 同名多个、CAB 对不上` | 补丁不是这批资源，跳过是对的，不要强装 |
| 中文文件名乱码 | 本机缺 `unzip -O` 与 `python3`；改用 APP 安装该包 |
| `✗ 解压失败` 并带 `unzip 报错：…` | 按报错判断：`invalid UTF-8 filename` 属编码问题，装个 `python3` 或换 Info-ZIP 的 `unzip`；`unsupported compression method` 说明包用了本机不支持的压缩算法，改用 APP |
| `data/...` 新文件没装 | 默认已经会按归一化路径新增（`data`、`flies` 及其它真实一级目录都行）；如果日志写“严格模式已跳过新增”，说明运行时带了 `--strict`，去掉即可 |
| `备份校验不符` | 索引里记的和备份文件实际校验值不一致，脚本保留原索引、回滚会跳过该文件；先确认备份是否被改动，必要时用 `--repair-index` 查看全量情况 |
| `定位不到目标（同名候选 0 个）` | 游戏里没有这个文件名。首级目录在游戏 `files` 下存在时（`data`、`flies` 等）会按归一化路径新建；首级目录不存在、或路径含 `..` / `assets/` 时不建，日志会写明 |
| 绝对路径包没装上 | 只有带 `files/` 根的包才直装；`/sdcard/...` 不在游戏 files 下、或路径属于其他包名的会被拒绝，日志会写明原因 |
| `只解出 N/M 个文件` 提示 | 已按文件条目统计，正常不该再出现；若出现说明包里有解不出的条目，看上一行 unzip 报错 |
| `✗ 已有一个安装进程在跑` | 等前一个跑完；确认真没有进程时删掉 `LvShu/酸败补丁/.install_su.lock` |
| 回滚时 APP 看不到新备份 | 确认备份在 `备份文件/<包名>/原版/` 下，且包名与 APP 当前游戏目录一致 |

## 7. 安全提醒

- 脚本以 root 运行，只操作 `LvShu/酸败补丁` 与游戏 `files` 目录，不碰其他路径。
- 打包脚本已拒绝 `..`；安装脚本只写解析出来的游戏路径。
- 公开包里不要带 `keystore.jks` 和明文口令；对外只发 `lvshu.cer`。
